# Illiria web

The Illiria web app: Vite + React 19 + TypeScript, Tailwind CSS v4, shadcn/ui on Base UI, TanStack Query,
React Router (data mode), react-hook-form + zod. It talks to the API in `../src/Illiria.Api` through a client
generated from the API's OpenAPI document.

## Getting started

Requires Node 24 and pnpm (the version is pinned in `package.json` → `packageManager`):

```bash
corepack enable          # or install pnpm yourself
pnpm install
pnpm dev                 # http://localhost:5173
```

The dev server proxies `/api` and `/health` to the API at `http://localhost:5080` (override with
`ILLIRIA_API_URL`), so the app and the API share one origin, exactly like production behind Caddy. Start the API
first (from the repository root):

```bash
docker run -d --name illiria-pg -e POSTGRES_USER=illiria -e POSTGRES_PASSWORD=illiria -e POSTGRES_DB=illiria -p 5432:5432 postgres:17-alpine
cd src/Illiria.Api && dotnet run -- migrate && dotnet run
```

The API sends email through SMTP on `localhost:1025` in development; a catcher such as
[Mailpit](https://mailpit.axllent.org) (`docker run -d -p 1025:1025 -p 8025:8025 axllent/mailpit`) shows them
at http://localhost:8025. The links in those emails open this app (`/confirm-email`, `/reset-password`,
`/invitations/accept`).

## Scripts

| Script | What it does |
| --- | --- |
| `pnpm dev` | Dev server on port 5173. |
| `pnpm run build` | Typecheck, then production build into `dist/`. |
| `pnpm run lint` | ESLint (typescript-eslint, react-hooks, react-refresh). |
| `pnpm run typecheck` | `tsc -b` for the app, the configs and the e2e tests. |
| `pnpm run api:gen` | Rebuilds the API's OpenAPI document (`dotnet build … -p:OpenApiGenerateDocuments=true`), then `api:types`. |
| `pnpm run api:types` | Regenerates `src/api/schema.d.ts` from `../src/Illiria.Api/openapi/illiria.json` (no .NET needed). |
| `pnpm run test:e2e` | Playwright end-to-end tests (see below). |

## API client

`src/api/schema.d.ts` is generated by [openapi-typescript](https://openapi-ts.dev) and committed: run
`pnpm run api:gen` whenever the API changes, and commit the result with the API change.

`src/api/client.ts` is an [openapi-fetch](https://openapi-ts.dev/openapi-fetch/) client: fully typed paths,
params and bodies. It sends the auth cookie (`credentials: "same-origin"`) and adds `X-CSRF: 1` to every
non-GET request, which the API requires. Wrap calls in `unwrap()` to get the data or an `ApiError` carrying the
response's ProblemDetails:

```ts
const projects = await unwrap(api.GET("/api/orgs/{orgId}/projects", { params: { path: { orgId } } }))
```

Auth is an HttpOnly cookie set by the API: no token is ever readable by JavaScript or stored in the browser.
`localStorage` only remembers UI preferences (the last organization used).

## Conventions

```
src/
  api/          generated schema, typed client, ApiError
  app/          router, app shell (top bar + navigation), route error page
  components/   shared components; ui/ holds the shadcn/ui components
  features/     one folder per feature
    <feature>/
      api.ts        query options + mutation hooks for the feature's endpoints
      pages/        route components
      components/   components used only by this feature
  lib/          framework-free helpers (query client, forms, roles, returnTo…)
e2e/            Playwright tests
```

- **Server state lives in TanStack Query.** Each feature exports `xxxQueryOptions()` (usable in loaders and
  components) and `useXxx()` mutation hooks that invalidate what they change. Query keys of organization data
  start with `["orgs", orgId]`.
- **Pass per-call data through `mutate(variables, callbacks)`**, not through state the hook closes over.
- **Mutation errors** show a toast automatically. Forms opt out with `meta: { handlesErrors: true }` and call
  `applyApiError(form, error)`, which puts the API's validation errors on the matching fields (or a form-level
  error).
- **Route guards are loaders**: `requireMe()` loads `/api/me` or redirects to `/login?returnTo=…`;
  `organizationLoader` checks membership for `/orgs/:orgId/*`. `returnTo` only accepts same-origin paths.
- The UI hides what a role can't do (`useCurrentOrganization().isAdmin`), but the API is the authority.
- `features/projects` is the reference feature: copy it for a new organization-scoped resource.

## UI components

`src/components/ui` contains shadcn/ui components for the `base-nova` style on Base UI, written by hand (see
its README). `components.json` is set up for the shadcn CLI, so on a machine with access to the registry:

```bash
pnpm dlx shadcn@latest add <component>          # add one, e.g. tabs, tooltip
pnpm dlx shadcn@latest add <component> --overwrite  # replace a hand-written one with upstream
```

Theme tokens (light and dark) are CSS variables in `src/index.css`. Dark mode follows the operating system
(`prefers-color-scheme`).

## End-to-end tests

The Playwright tests run against the **real API** (no mocks); Playwright starts the Vite dev server itself.
New accounts must be able to sign in without confirming their email, so start the API with:

```bash
cd src/Illiria.Api && Identity__RequireConfirmedEmail=false dotnet run
```

Then, from `web/`:

```bash
pnpm exec playwright install chromium   # once
pnpm run test:e2e
```

Each run registers fresh `@e2e.illiria.test` accounts. Set `E2E_BASE_URL` to test an already running app
instead of starting the dev server.

## Package manager hardening

`pnpm-workspace.yaml` holds pnpm settings: versions younger than a day aren't installed
(`minimumReleaseAge`), and dependencies' install scripts are blocked unless listed in `onlyBuiltDependencies`
(currently none needs one; `strictDepBuilds` fails the install if a new dependency asks).
